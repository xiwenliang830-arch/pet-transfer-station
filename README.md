# 宠物中转站 V1

一款面向城市养宠人群的离宠照护协作原型，解决主人出差、异地工作或搬家期间，照护计划、服务选择、宠物资料与交接记录彼此割裂的问题。

核心目标不是简单提供寄养信息，而是让一次照护从建立计划到完成关单持续、透明、可追溯。

## 核心流程

`建立照护计划 → 比较照护方案 → 生成宠物档案 → 交接与每日打卡 → 异常接力与关单`

## 主要功能

- 照护工作台：查看计划进度、每日任务、准备清单和最新反馈
- 四步计划向导：填写日期、照护任务、预算、紧急联系人和方案偏好
- 方案比较：统一比较价格、宠物适配、灵活性与信任保障
- 宠物数字档案：支持编辑资料和上传照片，并生成照护交接卡
- 双角色交接：区分主人视图与照护者视图，共同使用一条时间线
- 异常处理：支持照护打卡、备注记录、异常上报和备用照护说明
- V1 需求页：展示用户旅程、页面需求、交互验收与产品边界

## 页面预览

项目包含 6 个可点击页面：

1. 照护工作台
2. 新建照护计划
3. 方案比较
4. 宠物档案
5. 交接协作
6. V1 方案与验收

更完整的设计判断、答辩顺序和验收标准见 [V1方案说明.md](V1方案说明.md)。

## 本地运行

项目是纯静态网页，不需要安装依赖或启动后端。

直接双击 `index.html`，或在项目目录中启动任意静态文件服务器即可。

## GitHub Pages 部署

1. 打开仓库的 `Settings → Pages`
2. `Source` 选择 `Deploy from a branch`
3. 分支选择 `main`
4. 目录选择 `/ (root)`
5. 保存并等待部署完成

部署成功后地址格式为：

```text
https://<GitHub 用户名>.github.io/pet-transfer-station/
```

仓库已包含 `.nojekyll`，无需额外构建步骤。

## 数据说明

当前版本是前端交互原型。计划、档案、照片和打卡状态保存在浏览器 `localStorage` 中：

- 刷新页面不会丢失当前设备上的修改
- 换设备或换浏览器不会自动同步
- 不同访客拥有各自的本地数据

如果要实现真正的多人协作、账号登录和照片云端共享，需要增加后端数据库、身份认证与对象存储服务。
